# 测试策略

让绿色套件有意义的规则。命令归根 `AGENTS.md`；理由归 Agent Note。这是指导不是脚本。

## 分层（每层回答一个不同的问题）

- **Unit**：按模块的行为测试，测试与它锻炼的代码区域同住。偏向边缘情况、错误路径、事件顺序、并发竞态、契约回归的永久测试。每个 registry 有一个释放安全测试：释放贡献者，断言清理。
- **Coverage gate**：按文件 100% 行覆盖是 CI 的门，`test` 不是。未覆盖的行往往是该被删的死代码，不是该补的测试。行覆盖必要而不充分：它证明行跑过，不证明功能按交付方式工作。
- **真实外部 e2e**：带凭据地打真实 provider；没凭据自跳过，让无密钥 CI 与贡献者不被阻塞。自跳过不是成本信号——不要配给真实 API 测试。
- **期望输出**：无录制往返的 CLI/进程期望，与拥有它的 app/包/脚本同住。
- **录制快照**：以录制会话（或等价的确定性输入）作为回放输入与期望持久化结果；每个模型/协议/人类可见的非平凡变更在同 PR 添加或更新一个无密钥快照场景。
- **性能基准**：用户路径的时间/堆/缩放预算，用构建产物在普通运行时测，不用源码加载器。

新能力、生命周期或输出变体在**计划阶段**命名所需的每一层。

## 四原则

### 测真实入口路径

产品可见的模块需要一个**非 unit 的真实组合测试**：通过真实的加载器/CLI/进程启动，只 mock 外部服务或非确定输入，断言模型可见请求/日志、持久状态或用户可见输出。手装对象的套件不够：它绕过了加载路径、导出规范化、服务解析拓扑，正是 bug 藏身的地方。

"真实入口路径"意味着发布产物：包的 `bin` 在普通运行时下运行构建后的入口，暴露源码加载器掩盖的失败（settle 竞态、模块解析、被吞的加载失败）。真正缺失的配置要以非零退出。

### 验证世界，不验证自述

e2e 断言重跑命令或从外部重读文件；对 agent 自身输出做关键词探测会让作弊的 agent 通过。断言未触碰的文件字节相同。测试拥有自己的资源：在测试内创建、`afterEach` 释放（失败/重试/超时也释放）；共享 fixture 放普通的 `tests/harness`，不放另一个测试文件（导入一个 spec 会重复注册它的 describe）。

### 优先真实实现，只 mock 昂贵或非确定的边界

mock LLM 适配器、网络、时钟；下游全部真实。手写的替身只证明桥接搬了字节，不证明交付的工具按断言行为。恢复测试按步骤区分前/后块失败，证明失败块不产生消息或工具副作用。

### 守卫必须能变红

只有当回归会让它失败，守卫才算守卫。对新的静态/语料守卫临时引入被拒的案例观察预期失败；对普通回归在修复前观察失败；对竞态用屏障证明重叠（重复执行不是竞态测试）；对端口/socket/共享路径/子进程在修复包含跨进程隔离时并发运行独立测试进程。fixture 以自己的 deadline spawn 时，先断言没有信号或超时结束子进程，再断言退出状态。压力运行是补充，不替代确定性回归。

## 测试解析：只走源码平面

每个测试配置把 workspace 导入解析到 `src`，不通过包 `exports` 走到构建后的 `lib/`：那里的陈旧产物会加载模块单例的第二份拷贝。构建产物只被显式消费：`lib` 模式子进程与上述构建冒烟。

## 可靠性：按真实的执行拓扑建模

除非配置证明否则假设这些层会重叠：同一文件内的测试 → 不同文件/worker 进程 → 同一 job 内独立的测试/gate 进程 → 共享一台主机的不同 job。进程隔离不隔离端口、可预测的文件路径、外部服务、数据库、socket、继承的子进程。对每个获取的资源明确：所有者、原子分配机制、可观察的就绪信号、注册的清理、静止的完成信号。不要因为一个 fixture 缺隔离就把整个套件串行化：串行块保护不了另一个文件/进程/job 的主机资源。

### 原子分配

用资源所有者的分配器，不要"检查可用再占用"：网络 fixture `listen(0)` 并在监听后读分配地址；每测试私有的 `mkdtemp` 根；共享数据库/socket/会话/输出位置用每测试唯一命名空间；路径必须不存在时用独占创建；稳定的录制标识与临时传输地址分开（在 fixture 内翻译）。只作为解析输入或期望值的字面路径/URL 不是获取的资源。

### 隔离进程全局状态

`process.env`、cwd、假时钟、locale/时区、模块 mock、registry、console 钩子、`globalThis`、全局 `fetch` 拦截都是独占的可变资源。优先注入依赖或实例本地适配器。必须修改时：记录原值是缺失还是存在；恢复到精确状态；立即注册恢复；最小修改范围用 `try/finally`；本地 `finally` 之前可能失败就保留 `afterEach` 兜底；只拦截 fixture 拥有的那个精确请求。

### 尊重平台语义

同一套件跑 Windows 与 POSIX。写回值只在断言容忍写回失败时安全；Windows 环境变量名大小写不敏感；Windows 异步释放文件句柄，rename/remove 需要按观察到的争用大小的有界重试；Windows 无 POSIX 权限/信号语义——依赖它们的案例显式按平台跳过并说明原因，而不是到处弱化断言。

### 超时预算对齐 lane

`describe`/case 的超时覆盖 runner 的 `--testTimeout` 而不是让位于它：低于 lane 预算的值在 CI 上收紧了已经授予的额度。进程创建主导的套件用 lane 预算；更紧的值要写明为何更紧。随 case 预算同时提高 hook 预算。超时本身是被测对象时，外层等待远大于被测超时。

### 按状态同步

固定 sleep 不是 setup 完成或 cleanup 结束的证据。等待显式就绪事件、握手、状态转换、拥有的 promise 或可外部观察的条件；用 deferred promise/屏障把竞态放在确定点；超时只用来界定等待，永不作为让断言正确的条件；不断言调度器相关的顺序，除非那是被测产品行为；时间本身是对象时注入或伪造时钟并总是恢复真实计时器。

### 拆卸到静止

获取后立即注册清理，让断言失败也释放。清理要停止新回调/请求、detach 监听、恢复全局钩子、终止拥有的工作、**等待**子进程退出/服务器关闭/worker 终止。只调 `abort()/close()/kill()` 不等完成信号是不完整的拆卸。

## 拒绝掩盖 flake 的修法

对确定性的本地测试，这些不是根因修复：不识别所等状态就加大超时；加重试；全部文件串行；吞错误或 unhandled rejection；弱化断言；normalize 掉不稳定行为；清理或断言前加 sleep。重试只对文档化的瞬态外部 provider 测试有效，留在外部边界。恢复预算不是掩盖：把套件提回它本来就有的 lane 预算、按运行器实测争用大小的有界重试，都是命名了所等工作。

## 诊断已有 flake

对已存在的概率性 CI 失败：先按拓扑分类（同文件/跨文件/跨进程/跨 job），收集失败日志里的 PID/文件/退出码/信号，找共享资源与未等待的完成信号。只请求诊断时保持只读：报告原因与证据，除非用户也要修复。

## 验证与报告

跑受影响行为的最小聚焦回归。只在变更拥有该风险时追加拓扑特定证据：全局修改→恢复证据；生命周期/子进程→静止拆卸证据；端口/socket/共享路径→并发独立进程证据；新守卫→负向对照。push 前按 [dsdev-pre-push-checks](../dsdev-pre-push-checks/SKILL.md)。报告精确命令与观察结果；不把重试、跳过、pending CI 描述为通过。
