# Agent 体验：模型可见文本的写法

- **从最小上下文开始**：先暴露目的、可用动作、约束；详细指令按需加载。
- **让发现显式**：每个延迟加载的资源有清晰描述与可靠的获取方式。
- **关键约束保持可见**：权限、破坏性效果、必需验证出现在相关动作之前。
- **偏好有界输出**：返回简洁结果加可检索细节的标识符或路径；不倾倒整份日志或文档。
- **利用局部性**：随操作结果附带有限量的、可能需要的相邻上下文（例如回复线程时带几条前文）。显式标记省略与截断并提供获取更多的方式。
- **评估总工作量**：节省上下文只在不引起更多搜索、重复读取或错误时有用。

## 工具定义

- **删掉显然的约束**：模型能从调用结果学到的规则（读不存在的文件会失败）不写。
- **描述行为，不描述实现**：工具做什么、返回什么；不写内部机制、模型在结果里会看到的输出标记、强制细节。
- **参数规则放参数上**：默认值、范围、配对、何时设置写在该参数的描述或 schema 里；随配置变化的描述通常意味着变化部分属于某个参数。
- **每个事实说一次**：不在系统提示词章节重复工具定义，不在工具描述重复参数描述，不在一个工具里写另一个工具的规则。
- **测量变化**：改工具定义前后比较首轮提示词 token 数。

## skill 的写法

- frontmatter 只有 `name` 与 `description`；`description` 写成**触发条件**（"在 … 时使用"），不写功能广告。
- 正文第一段说明它拥有什么、不拥有什么，并声明"这是指导不是脚本/清单"。
- 工作流简洁；真相来源用链接，不复述。
- 行为护栏与范围限制明确（排除 vendor、归档树；只读任务不写）。
- 结尾规定报告格式：只报告实际运行的命令。
- 领域规则留给仓库的 `AGENTS.md` 与 defensive-patterns；skill 只放方法。
