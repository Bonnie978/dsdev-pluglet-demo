# 防御模式

每条模式是本仓库在 review 中执行的要求：规则本身、它防止的缺陷、评审判定条件、边界与谁批例外、正确与错误示例。改某类工件前读对应页。

## 为什么是这些规则

五个习惯覆盖大部分内容：

- **让正确性显式**：写进结构（命名的调用点、显式生命周期、显式条件与类型），不靠时序补救。
- **单一真相源**：一份数据一条读路径，一个事实一个家，共享状态一个所有者。
- **通过注册的扩展点扩展**：新能力注册进来；现有载体不再长分支。
- **变更面等于评审面**：一个变更只带其行为变化需要的行，迁移搬代码不重写，性能变更带测量。
- **要求证据**：声明可证伪、可重算——前后测量或 gate 检查，而不是靠人手同步。
