# 寻找简化

找能移除**被维护的义务**的改动：API、表示、生命周期状态、配置路径、依赖、测试、文档。宁要几个有充分支撑的候选，不要删除行数。这是指导不是清单；守住用户给的范围，区分"调查"与"获准实施"。

## 建立范围与约束

读 `AGENTS.md`、架构文档、defensive patterns、测试策略；查相关活跃 Agent Note 里的有意决策，归档 note 只是历史示例。项目声明为"有意保留"的设计（例如双实现、协议 seam）不提议删除，除非用户明确覆盖；受保护设计内未使用的成员仍是候选，只要移除保留其目的。

范围大时按独立领域分给子 agent：每个 agent 一个有界领域，要求消费者证据与被拒的备选。既看明显未用的符号，也看实质的生产机制；别在第一个有希望的删除处停下。

## 用这些问题发现可删的义务

- **声明的功能有完整的效果路径吗？** 追生产者、变换、provider/端点支持、可观察结果。到处被复制的字段可能没有 setter、没有 reader、或只有拒绝它的实现。
- **哪些区分会改变消费者的行动？** 多个内部状态可能只需要一个对外状态。保留控制授权、驻留、持久性、所有权的内部区分；删除只会引来无用选择的公开区分。
- **更小的显式行为能删掉整个子系统吗？** 固定间隔、调用者提供的时区、报告激活失败，可以消灭通用日历、持久默认值、自动回滚。写明放弃的能力与删掉的机制。
- **消费者需要时能读权威值吗？** 找复制的历史、晋升账本、失效事件后的读取、共享投影流旁的功能缓存。派生或复用可能一起删掉订阅、保留数据、过期响应处理、恢复路径。
- **组合被误当成策略了吗？** 可选服务的存在、provider 方法、兄弟工具可以表达可用性而不决定部署行为。显式配置或调用意图操作可能删掉 registry 与依赖检查。
- **谁拥有完整的维护成本？** 追透传配置、重复的应用树、产品用的 demo 启动器、只做解析的 workspace、有自己升级生命周期的安装助手。比较整个被删系统与替代（含残余胶水）；搬动复杂性或加一个 gate 保持重复定义相等不是移除。

## 证明可达性与取舍

先 `rg` 再读匹配。搜精确符号、属性读写、判别值、事件与线上字符串、配置键、包名、`.method(` 与 `method(` 两种形式。测试与声明能显示契约，不能证明有交付的生产者或消费者。覆盖源码、应用、运行时脚本、交付的配置、包清单与 exports、加载器解析、生成的运行时资产、已安装包的消费者。按真实入口分类示例与 fixture。生成目录追到消费者：被模型写的插件挂载使用的目录是动态产品 API，仅文档用的清单不是固定调用者。公开的第三方扩展路径可能零仓库调用点也是有意的。

每个候选记录：当前所有者、有效的生产者/消费者路径、消失的、留下的、最强的保留理由。区分：移除不可达/未读行为；带显式损失的更窄公开行为；受保护义务或证据不足。候选破坏保留义务、仅搬动复杂性、或没有有意义的减少 → 拒绝。拒绝理由按提议变更的层级读：陈旧的清单或混合提案里被拒的行为不决定每个独立项。小的局部改进放 `TODO/FIXME/XXX` 注释，不写独立设计记录。

## 保留所有权与失败语义

对拷贝、冻结、验证器、回调捕获，命名值的来源、下一个所有者、信任边界。同进程类型化调用通常借用只读值；解析器、配置加载器、队列、模型/工具 JSON、持久文件、worker、进程、线上解码器拥有或验证输入。敌意 getter 或回调替换测试本身不建立需求。

对异步机制，把每个 promise、标志、取消路径、释放器、预留映射到所有者与转换。只在表达同一事实时折叠机制。保留同步发布与回滚、回调隔离、首个终态仲裁、worker/进程所有权、释放到静止。

## 只为净减少替换基础设施

先搜现有依赖与引擎下限的内建。识别替换会删掉的精确实现与专用测试、维护与传递成本、胶水必须保留的每个残余行为。练最可能击败替换的错配：协议截断、取消与拆卸、配置界限、确定性测试时钟、平台打包、源码 vs 构建入口。覆盖了帧但要重建同样的帧来执行大小限制的库不是简化。

## 记录、合并、验证

散文在范围内时按 [dsdev-doc-standard](../dsdev-doc-standard/SKILL.md)。实质提案用 proposed Agent Note 骨架（Problem/Proposal/Alternatives considered/Acceptance criteria/Risks），含具体消费者证据、移除的维护成本、放弃的能力、可观察的验收条件。已实施的决策用 implemented 格式。决策相同就更新已有所有者，不为保留候选数建重复 note。每个新 note 做取代检查（[dsdev-agent-note](../dsdev-agent-note/SKILL.md)）。

折叠另一分支时，对目标 base 比较其独立 diff，只移植有支撑的不重叠提案，合并重叠理由。关闭别人的 PR 需要授权。

验证按 [dsdev-pre-push-checks](../dsdev-pre-push-checks/SKILL.md)。报告：调查的区域、有支撑的候选、有意义的拒绝/推迟、新增/合并/保留/删除的 note、实际运行的命令。调查扩展中用 draft PR；不把未验证的搜索描述为穷尽。
