# 错误处理

定义失败、它们的所有者、失败后什么仍然安全。

## 类型化、结构化的失败

预期失败需要声明的类型、稳定的判别值、与处理相关的细节。复用模块的错误约定，保留 cause，把机器身份与显示文本分开。**永不靠解析消息文本路由处理。** 意外缺陷（如 `assertNever`）可以保持普通 `Error`；隔离绝不能把它们变成成功。

## 捕获、恢复或停止

对每个失败，在拥有的 API 文档里定义处理与报告的所有者、隔离、保证：有效的不变量、效果是缺失/部分/已提交/未知、清理责任。后台工作保留这些义务。

捕获限制的是异常传播，不是变更。只有受影响状态的所有者能建立安全的继续；否则停止依赖它的工作、丢弃无效状态或实例、或上报。**只记日志不是恢复。** 重试需要安全的可重复性、取消、明确的所有者；有限操作需要预算，持续的监督需要生命周期所有权与可观察的降级。

空 catch 要命名错误与为何可忽略，其 `try` 块只放一条语句。

## 本地化、可行动、可见的报告

每个最终报告需要可读的摘要、受影响的操作、安全的下一步。有 locale 机制的应用通过它本地化；其他诊断用现有输出语言。敏感内部细节不进用户可见文本。

不可信状态或未知结果必须通过 UI 或默认开启的可访问日志可见：报告影响、不确定性、系统处置、安全的下一步。持久的无效状态需要持久的可见性。没有保证时不声称成功、回滚或可安全重试。报告失败本身需要独立的兜底。

验证结果状态与可见结果，不只验证异常被捕获了。

## 根基

Meyer《Object-Oriented Software Construction》（契约与不变量）；Sutter《Exceptional C++》（异常安全保证）；Armstrong 博士论文（隔离与监督）。
