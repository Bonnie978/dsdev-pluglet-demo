# 评审 PR

**这是指导，不是完整清单。** 先确认并 fetch PR 的真实 base 与精确 head，生成变更范围报告，然后读 diff 和足够的周边代码理解设计。范围报告标出路径，不替代语义评审。重定向或合并后重新建立 base 并重跑。优先级：正确性、生命周期、安全、被破坏的必需行为 > 风格；一条有实据的阻断项胜过一列 nit。

**先读需求再判 diff。** 把变更路径映射到工件，打开各工件的权威页面（见下），然后才对着这些要求读 diff。凭记忆判规则是违规漏过评审的方式。

## 真相来源

- 根 `AGENTS.md` 与子树 `AGENTS.md`：常备的仓库与模块编写规则。
- `docs/defensive-patterns/`：变更必须满足的架构要求与背后的习惯；每页拥有一个工件，diff 触及哪页就读哪页。
- `docs/AGENTS.md` 与 [dsdev-doc-standard](../dsdev-doc-standard/SKILL.md)：文档放置与散文纪律。
- [dsdev-testing-policy](../dsdev-testing-policy/SKILL.md)：必需的测试层、隔离与防回归规则。
- [dsdev-error-handling](../dsdev-error-handling/SKILL.md)：失败分类、处理所有权、状态保证、可行动报告。
- Agent Notes：设计理由。与 note 的分歧是设计讨论，不是自动否决。
- postmortems：这类改动曾经怎么逃逸。

## 阻断要求

1. **新散文要语义评审。** 每段新增/修改的 Markdown、JSDoc、注释、提示词、描述、诊断、可见字符串都对着拥有的代码核对覆盖、准确、放置与编辑质量；自动检查不能证明这些。 具体地查三样：契约是否完整（行为、失败、所有权、时机）；放置是否在它的家（变更故事只住升级指南/Agent Note/PR 正文）；有没有思维链泄漏——当前状态面（README、JSDoc、注释）里出现旧名字、版本号、"no longer"、"替代了 X"、对评审者的辩护，都是阻断项，哪怕只有半句。
2. **文档与代码一致。** 配置、默认值、错误、线上字段、事件、公开行为在同一 diff 更新 README 与 JSDoc。注释陈述非显然契约；实现叙述、测试走读、评审历史、重复的理由标记为删除或改链到唯一的家。
3. **核心类型文档一致。** 改动核心词汇/类型要更新对应的子系统页与粘贴校验条目。
4. **注册与清理。** 每个新的注册贡献通过释放（dispose）测试；单例状态、未撤销的副作用、消费者尚未结束就释放的清理依赖是 P0。
5. **必需证据存在。** 核实作者跑了与 diff 相关的本地检查、CI 覆盖了全量矩阵，然后评审两者都查不出的语义缺口。
6. **用户可见文案归本地化字典**（若项目有本地化机制）：拒绝写死在模板/辅助函数返回值/可访问性属性里的产品文案。

## 人工检查

- **意图与接口契约**：追每个改动接口的两侧；实现与 PR 描述、Agent Note 一致，包括错误、取消、所有权、释放。
- **错误处理**：拒绝 catch-and-continue，除非状态所有者证明后续工作的前置条件成立。
- **生命周期与并发**：发布前的竞态、await 期间的取消、独立的错误报告、回调隔离、重入前的所有权、完整的 detach 清理、静止的释放。
- **能力与消费者匹配**：追每个当前消费者；消费者特有行为泄进接口要标记。反向也标：通用服务上只有一个内部调用者的新公开方法是不必要的 API 扩张——改为构造时传入私有能力闭包。
- **范围、所有权与必要性**：每个抽象、状态机、选项、防御性拷贝、兼容路径对应当前的契约、生产消费者与拥有模块。挑战无关功能与投机性的通用化。
- **配置与公开选择**：每个默认值、公开操作集、格式、引入的外部概念有什么当前消费者证据或先例？没有就要求显式选择或推迟。
- **模型视角**（若涉及模型可见内容）：检查模型实际收到的提示词、工具 schema、结果、诊断；标出任务之外的概念；稳定文本按字面固定，动态行为靠快照/e2e。
- **强制点**：每条拒绝路径追到执行它的操作；直接或替代调用者能绕过 schema、提示词、门面、包装器或监听顺序吗？
- **借用与派生状态**：每个保留的值按契约是借用还是拥有；通知与缓存/提示词/回放/查询视图追到文档化的成功点与唯一权威源。
- **边界覆盖最终结果**：字节/token/条目/时间上限在完整结果（含包装与元数据）已知处执行；探极小与精确上限、超大单块、多字节文本。
- **真实入口路径**：测试走真实的加载器/bin/worker/子进程；手装对象抓不到无效的导出。
- **测试强度**：断言对预期回归会红，验证外部状态/日志/事件/释放，而不是复述实现或信任 agent 自述。覆盖率必要但不是正确性证据。
- **测试可靠性**：资源占用、异步、平台敏感、flaky 的测试按真实 worker/job 拓扑检查分配、全局状态恢复、同步、超时预算、静止拆卸。
- **负向对照**：每条改动的接受规则有一个故意无效的案例通过真实 runner 失败。
- **implemented Agent Note 与上线事实一致**：PR 实现了一个 proposed note 就在同 diff 移动并改写为现在时，核对路径、名字、机制。
- **可见输出变更**：编辑器/模型可见的变化更新快照，或解释为何无快照适用；期望输出的 diff 当行为变更评审，不当格式噪音。
- **双语变更**：两边比对含义与术语；配对哈希绿不证明翻译质量。

## 报告发现

陈述缺陷、位置、影响、证据。局部缺陷放在最窄的 diff 范围行内；跨切面的架构、范围、评审综合用 PR 级评论。阻断项与建议分开；已被绿色 gate 执行的问题省略。回复用已有的评审线程。

## 收到评审时

逐条对着代码核实，然后修复或**以技术理由反驳**，不表演式同意。修复落在引入问题的 PR/层再向上传播。委托给子 agent 的修复是"信任但验证"：自己在真实树上重跑 gate；回归守卫要证明它在未修复代码上会红（引入回归、看红、还原）。子 agent 把问题重新表述为"已经处理"是亲自深挖的信号。重写推送后重读未解决线程、批准、可合并性、检查。
